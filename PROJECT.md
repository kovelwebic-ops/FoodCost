## 1. Що це

**FoodCost** — вебзастосунок для розрахунку собівартості й ціни продажу страв.
Створений для домашнього кондитера: внести ціни продуктів один раз, у рецепті
вказувати лише грамовки, а застосунок рахує собівартість, додаткові витрати,
маржу, ціну продажу, КБЖУ й алергени та робить техкарту в PDF.

- Інтерфейс **українською**.
- Без реєстрації, безкоштовно, дані живуть **лише в браузері** (localStorage).
- Репозиторій: https://github.com/kovelwebic-ops/FoodCost (публічний).
- Живий сайт: GitHub Pages з гілки `master` — https://kovelwebic-ops.github.io/FoodCost/

### Поточний стан (вересень 2026)

- Йде **відкритий тест із реальними користувачами**. Основний трафік — **з телефонів**,
  тому мобільна верстка має найвищий пріоритет.
- Власник надсилає скріншоти з телефона з позначками й дрібними правками;
  робота йде короткими ітераціями «правка → перевірка → пуш».

### Запуск

- Просто відкрити `index.html` у браузері — працює.
- Для превʼю/перевірки в інструментах, які не виконують скрипти з `file://`,
  потрібен статичний сервер. На машині власника **немає Python і Node**, тому
  використовувався PowerShell-сервер:

```powershell
$root = 'C:\Users\user\Desktop\FoodCost'
$l = New-Object System.Net.HttpListener; $l.Prefixes.Add('http://localhost:8765/'); $l.Start()
while ($l.IsListening) {
  $c = $l.GetContext(); $p = $c.Request.Url.LocalPath; if ($p -eq '/') { $p = '/index.html' }
  $f = Join-Path $root $p.TrimStart('/')
  if (Test-Path $f -PathType Leaf) {
    $b = [IO.File]::ReadAllBytes($f)
    $c.Response.ContentType = @{'.html'='text/html; charset=utf-8';'.css'='text/css; charset=utf-8';'.js'='application/javascript; charset=utf-8'}[[IO.Path]::GetExtension($f)]
    $c.Response.Headers.Add('Cache-Control','no-store'); $c.Response.OutputStream.Write($b,0,$b.Length)
  } else { $c.Response.StatusCode = 404 }
  $c.Response.Close()
}
```

### Деплой

Пуш у `master` → GitHub Pages оновлюється за 1–2 хвилини. Окремої збірки немає.
Назва `index.html` — **малими літерами** (Pages чутливий до регістру).

## 3. Функціонал (екрани)

Навігація: на компʼютері — сайдбар зліва; на телефоні (< 900px) — шапка з логотипом
і бургером, сайдбар виїжджає шухлядою справа.

1. **Головна** — два кроки: заповнити базу продуктів, створити калькуляцію.
2. **База продуктів** — назва, ціна упаковки, кількість в упаковці, одиниця (`г`/`мл`/`шт`).
   Пошук. Кнопки «+ Додати продукт» зверху й знизу списку. Якщо ввімкнено КБЖУ —
   кнопка «КБЖУ» відкриває редактор харчових даних і алергенів продукту.
3. **База витрат** — типові витрати (коробка, доставка…): фіксована сума або % від собівартості.
4. **Напівфабрикати** — заготовки (тісто, крем) зі своїм складом і **виходом** (скільки вийшло).
   У калькуляцію вставляються групою, перерахованою під потрібну кількість.
5. **Папки** — рецепти згруповані по папках; сітка карток з фото, собівартістю й ціною;
   пошук і сортування (А–Я / за ціною / нові); перейменувати/видалити папку.
6. **Калькуляція**:
   - Назва + фото (стискається до 720px, JPEG 0.72).
   - **Інгредієнти**: назва з автопідказкою з бази → ціна й упаковка підтягуються самі;
     користувач вписує кількість. Вставка напівфабрикату групою.
   - **Додаткові витрати** (підтягуються з бази витрат).
   - **Маржа** у % зі швидкими кнопками 30/50/80/100.
   - **Харчова цінність** (якщо ввімкнено): КБЖУ на 100 г і на весь виріб, алергени;
     «Вага готового виробу» — за замовчуванням сума інгредієнтів, можна переписати.
   - **Підсумок**: собівартість, витрати, маржа, ціна продажу, підказка округлення вгору.
   - Кнопки: «Зберегти/Оновити калькуляцію» (вибір папки), «Експортувати PDF», «Видалити».
7. **Налаштування**: валюта (₴ / zł / $ / €), округлення ціни (без / до 5 / до 10),
   КБЖУ та алергени (вимк./увімк.), тема (світла/темна), резервна копія у файл /
   відновлення з файла, скидання до демо-набору.
8. **Інструкція** — поки що **заглушка** (тост). Див. «Черга».

Додатково:
- **«Ціни змінились»**: якщо ціна продукту чи витрати в базі змінилась, збережені
  калькуляції й напівфабрикати пропонують «Перерахувати» (масово або по одній).
- **Експорт PDF (А4)**: прев'ю в модалці, документ сам підбирає кегль, щоб влізти в одну
  сторінку; якщо не влазить — кілька сторінок.
- **Історія браузера**: кнопка/жест «Назад» переходить між екранами застосунку.

## 4. Модель даних

Весь стан — один обʼєкт `S`, серіалізується в `localStorage['fc:state:v1']`.

```js
S = {
  currency: '₴', round: 5, theme: 'light', showNutrition: false,
  products: [], expenseBase: [], preps: [], folders: [],
  draft: null,                       // незбережена калькуляція
  ui: { screen, folderId, editing: {folderId, recipeId} | null, folderQuery, folderSort, prepId }
}

product    = { id, name, price, pack, unit, nutrition, allergens, pieceWeight }
  nutrition  = null | { kcal, prot, fat, carb }   // на 100 г; окреме поле null = не вписане
  allergens  = null (не вказано) | [] (немає) | ['gluten', 'Мед', …]
  pieceWeight= вага 1 шт у грамах (лише для одиниці 'шт')
ingredient = { name, price, pack, unit, qty, g? }  // g = id групи напівфабрикату
expense    = { name, mode: 'sum' | 'pct', value }
prep       = { id, name, ing[], yield, unit }
group      = { id, prepId, name, take, of, unit }  // напівфабрикат у рецепті
recipe     = { id, name, photo, margin, ing[], exp[], groups[], outWeight }
folder     = { id, title, recipes[] }
```

### Формули (`app.js`, розділ 5)

```
вартість рядка      = price / pack × qty
витрата 'pct'       = собівартість_інгредієнтів × value / 100   (не від суми з витратами — без циклів)
разом (sub)         = cost + extra
маржа               = sub × margin / 100
ціна продажу        = sub + маржа
округлення (round)  = ceil(price / step) × step
напівфабрикат: ціна одиниці виходу = собівартість замісу / yield
КБЖУ: грами рядка ('мл' ≈ 'г'; 'шт' → × pieceWeight), на 100 г = сума / вага × 100
```

## 5. Ключові правила даних (не порушувати)

1. **Ціни в рецепті — копії**, знімок того, за скільки рахували клієнту. Вони мають право
   застаріти; оновлюються лише явним «Перерахувати». **КБЖУ й алергени — НЕ копії**:
   беруться з бази **за назвою** в момент показу.
2. **Міграції.** Дані в localStorage живуть безстроково й записані старими версіями.
   **Кожне нове поле додавати в `normalize()`** (вона ж обробляє імпорт із файла).
3. **Обробник збереження рецепта** (`bindSave` → `#save-confirm`) перелічує поля рецепта
   **вручну**. Нове поле рецепта треба додати й туди — інакше воно тихо зникає при збереженні
   (так уже було з `groups`).
4. **Алергени — три стани**: `null` = не вказано, `[]` = немає, `[…]` = є. Ніколи не
   зводити `null` до `[]`: «не вказано» не має читатися як «безпечно». Зняли останній
   чип — повертаємось у `null`.
5. **Алергени**: базові — 7 ключів (`gluten, eggs, milk, nuts, peanuts, soy, sesame`);
   решта — **свої назви**, які вписує користувач. Будь-який список проганяти через
   `normalizeAllergens()` (дедуп без регістру; «молоко» → ключ `milk`; старі ключі ЄС із
   `LEGACY_ALLERGENS` → свої назви). Порівнювати через `alKey()`. **Свої назви екранувати** (`esc`).
6. **КБЖУ вимкнено за замовчуванням** (`S.showNutrition`). Один клас `nut-on` на `<html>`
   ховає/показує всі `.nut-only` блоки. Дані не видаляються при вимкненні.
7. **Порожнє поле КБЖУ зберігається як `null`**, а не 0 — інакше «витерте» значення
   перетворювало б продукт на «заповнений нулями».
8. **`outWeight: 0` = авто** (сума грамів інгредієнтів, показується сірим у полі).
   Зберігається лише число, вписане вручну (`data-manual` на полі).
9. **Напівфабрикат у рецепті не згортається в один рядок**: його складники лежать у тому
   ж `r.ing` плоским списком з міткою `i.g`. `totals()`, PDF і збереження бачать звичайні рядки.
10. **Звірка з базою** (`syncWithBase`): кількість у страві не чіпається ніколи; якщо в базі
    змінилась одиниця — рядок пропускається (300 «г» не можна перечитати як 300 «шт»).
11. **Запис у сховище** відкладений на 300 мс (`persist()`), плюс примусово на `beforeunload`.
    Переповнене сховище — не мовчати (статус «Не збережено на пристрої»). Пошкоджений JSON
    відкладається в `fc:state:v1:broken`, а не перетирається демо-даними.
12. **Імпорт з файла замінює все** — спершу показати, що прийде, і попросити підтвердження.

## 7. Верстка й мобільна версія

### Брейкпоінти (`styles.css`, розділ «Адаптив» наприкінці)

- **≤ 900px** — шапка телефона + бургер, сайдбар стає шухлядою; липкий пошук.
- **≤ 760px** — таблиці стають **картками на сітці** (підпис над полем з `data-lbl`),
  рядки згортаються, модалки — шторки знизу, тіні на блоках.
- **> 900px — компʼютер. Мобільні правки не мають його змінювати.**

### Патерн «згорнутий рядок» (телефон)

Бази продуктів/витрат, інгредієнти й витрати калькуляції, склад напівфабрикату:

```
Борошно вищий ґатунок              18,00      ← назва + вартість
45,00 ₴ за 1000 г / 400 г              ⌄      ← опис + шеврон під вартістю
```

- Згорнутий рядок нічого не редагує; тап будь-де відкриває його (`.is-edit`), шеврон ⌃ біля
  назви закриває. Порожній новий рядок відкритий одразу.
- Фіксована витрата — **один рядок** без опису («Коробка 15,00»); відсоткова — з описом
  «5 % від собівартості».
- У відкритій картці бази видалення — текстом «× Видалити» внизу, не хрестиком у шапці.
- Розмітка одна для компʼютера й телефона; `.row-peek`/`.row-fold` на компʼютері приховані CSS.

### Інші рішення

- Заголовки панелей на телефоні — тонована смуга, 18px/700, щоб не зливалися з рядками.
- Шапка калькуляції компактна: назва 24px і кнопка фото-іконка в одному рядку.
- Шапка телефона вирівняна по краях контенту (16px, на планшеті 20px).
- PDF-прев'ю на телефоні масштабує аркуш цілком; **ширину документа не міняти** —
  html2pdf знімає той самий вузол (масштаб знімається перед експортом).
- Z-index: шухляда 50 < шапка 60 < модалки 70 < тост 80.
- Калькуляцію видаляють кнопкою «Видалити» в підсумку; **хрестиків на картках папки немає** (свідомо).

## 8. Пастки, на яких уже спотикались

1. **Автовідновлення полів мобільним браузером.** При перезавантаженні вивантаженої
   вкладки браузер відновлює значення полів без імені **за порядком у DOM** — цифри
   роз'їжджались по чужих рядках. На **кожному** `input`/`select` стоїть `autocomplete="off"`.
   Нові поля — теж.
2. **iOS зумить сторінку** на полях < 16px. На телефоні всі поля 16px. Правило
   `.inp { font-size:16px }` має ту саму вагу, що `.title-inp` — тому для винятків
   потрібна вища специфічність (`.inp.title-inp`, `.inp.al-add`).
3. **`button { white-space: nowrap }` глобально** — текст усередині кнопок (напр. назва в
   згорнутому рядку) не переноситься, якщо не задати `white-space: normal`.
4. **`flex: 1` у стовпчику** (`flex-direction: column`) дає висоту 0 — кнопки сплющувало.
5. **Рядок редактора КБЖУ (`.nut-row`) теж має `data-id`** продукту — селектори продуктів
   пишіть як `tr[data-id]:not(.nut-row)`.
6. **Специфічність ID-правил**: `#s-calc.is-active` перебивало мобільний відступ `.screen`.
7. **`align-self` у фіксованого флекс-дочірнього** елемента підрізало висоту шухляди.
8. **NUL-байт у файлі** (колись потрапив через `'\u0000'` у правці) робить `app.js`
   «бінарним» для git і ламає диф. Не вставляти керівні символи.
9. **Тестування в браузерному превʼю**: запис у сховище відкладений і повторюється на
   `beforeunload`, тож підкладені вручну в localStorage дані перетираються до
   перезавантаження (для тесту міграції тимчасово глушили `Storage.prototype.setItem`).

## 9. Стиль коду й комітів

- ES5-стиль, один IIFE, без збірки. Нові функції — поруч із тематичним розділом.
- **Коментарі українською**, пояснюють **чому**, а не що. Щільність — як у навколишньому коді.
- CSS: токени кольорів у `:root` і `html[data-theme="dark"]`; кольори тіней/ліній — з токенів,
  щоб темна тема працювала сама.
- **Коміти англійською**: заголовок + тіло з поясненням причини й рішення.
- **Пуш після кожної завершеної й перевіреної зміни, не питаючи** (див. домовленості).

## 10. Домовленості з власником

- Спілкування українською, відповіді конкретні, без води.
- **Пушити завжди після кожної зміни** (не питати «пушити?»).
- **Перевіряти мобільні зміни на 320 і 360px** (без переповнень, накладань, обрізаних
  значень) і що **компʼютер не змінився**. Бажано також темну тему.
- «**Мʼясо**» = візуальний шум/перевантаження. Власник цінує повітря, рівну сітку, точне
  вирівнювання країв.
- Підписи в інтерфейсі — **короткі й прості**.
- **Анімацій появи сторінок немає** (прибрані на прохання); лишились лише анімації взаємодії.
- Додавання в списках — кнопки **і зверху, і знизу**.
- Без зеленого підсвічування «знайдених у базі» продуктів.
- КБЖУ — **лише ручне введення**, вмикається в налаштуваннях; **без бази стандартних
  продуктів і без Open Food Facts** (можливо, пізніше).
- Демо-дані — реалістичні (напр. витрата «Амортизація обладнання 1%»).

## 11. Черга й ідеї

- **Інструкція** — окремий екран замість заглушки (кроки: база → калькуляція → папка → PDF,
  налаштування, КБЖУ). Відкладено як завелику для серії дрібних правок.
  **Після запуску — оновлювати її з кожною новою функцією.**
- Попередження «Є незбережені зміни — вийти?» при «Назад» / «← Папка» з калькуляції
  (зараз зміни тихо губляться, як і раніше).
- Фото страви в PDF (свідомо поки не йде в експорт).
- Синхронізація між пристроями / акаунт (зараз лише резервна копія у файл).
- Опційно: картки папки у 2 колонки на телефоні.
